# 2026.318.0533 — fix(image): match the built image by the box's leaf name, so a remote-ref build resolves

## Summary

`charly firecracker image build '@github.com/<org>/<repo>/box/<name>:<ref>'` **built the image and then failed its own lookup**:

```
$ charly firecracker image build '@github.com/opencharly/layer-fireactions-runner/box/fireactions-runner:1e3e39f…' --ref localhost/fireactions-runner-proof:1 …
firecracker image build …: the box build produced no image matching "@github.com/opencharly/…:1e3e39f…": the engine has no such ref

$ podman images | grep fireactions
localhost/fireactions-runner   2026.318.0517   2.02 GB   (built 39 seconds ago)
```

The build tags `localhost/<leaf>:<calver>`; `pickImageRef` matched the RAW argument, which names no image in the engine, so a remote-ref build could never satisfy its own lookup. It now reduces the argument with `boxLeaf()` — strip `@host/`, a `:ref` suffix, and every path segment before the last — and matches the leaf. A bare local name passes through unchanged.

**The discriminating test** (`TestPickImageRef`, remote-ref arm) fails without the change: with the raw-argument match, `pickImageRef(remoteLines, "@github.com/…/box/fireactions-runner:1e3e39f…")` returns `("", false)` — which is exactly the reported error. `boxLeaf` is asserted for the remote form and for the bare name.

**A1/R10, stated rather than implied:** this is a pure LOOKUP function inside the producer — the change is which string it matches, with no new runtime path, no new dependency and no new artefact. Its discriminating proof is the test above, and its live proof runs on the HOST with the changed code served (`CHARLY_REPO_OVERRIDE`), because the shape that failed is a remote-ref build and the host is where that shape reproduces in one command. The product's disposable bed for this producer (`check-firecracker-producer-vm`) covers the same producer end to end on its local path and is unchanged by this diff; the consumer bed that exercises the remote-ref shape is `layer-fireactions-runner#2`. The tier is therefore `analysed on a live system`, not `fully tested and validated`.
