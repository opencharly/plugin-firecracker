## Summary

**A repo-local check that fails when the candy's `plugin.providers:` claims a class this plugin does not serve** — the failing-without coverage three previous verdicts asked for. **And it immediately disproved the change those verdicts were about, which is why this PR no longer contains a `deploy:firecracker` declaration.**

Diff, read from `git diff --stat origin/main` before this body — **one file, +84**: `candy/plugin-firecracker/declared_words_test.go`. The `deploy:firecracker` line added in the earlier rounds is **withdrawn**, so the diff is the check and nothing else.

## What the check found

Run against the tree as it stood:

```
--- FAIL: TestDeclaredWordsMatchServedClasses (0.00s)
    declared_words_test.go:80: charly.yml claims 1 provider word(s) this plugin does not serve:
        deploy:firecracker (served classes: command, verb)
```

That is a true finding, and it is mine. `plugin.go` states that `classCommand` and `classVerb` are *"the two provider classes this plugin declares"*, and this repo's `AGENTS.md` is explicit: *"One provider must serve BOTH classes … This plugin must NOT claim `kind:firecracker` as well: two claimants for one word is the duplication R2 forbids."*

`deploy:firecracker` is a **third class, served by nobody here**. A declared word the binary cannot answer is *a route to a refusal — worse than an absent word, because the registry hands it out happily.*
